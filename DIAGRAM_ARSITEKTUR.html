CariUstadz — Alur Agent & Trust Boundary

cariustad-apps.vercel.app
Next.js 14 · App Router · region sin1
Challenge B — Agen Kantor
Zona 1 — Pengguna (browser)
1
Input pengguna — teks atau suara
Web Speech API (SpeechRecognition) untuk suara, atau kotak teks. Contoh: "saya mau booking ustadz untuk kajian, Senin jam 19:00, di Bandung, 50 orang"
Trust boundary 1 Semua input diperlakukan sebagai data, bukan perintah. Tidak ada instruksi pengguna yang dapat mengubah aturan agent.
Zona 2 — Agent (server Next.js, tepercaya)
2
Prompt Guard — 23 pola injeksi
Deteksi deterministik frasa Indonesia & Inggris: abaikan aturan, you are now, disregard, reveal your system prompt, jailbreak, [system:. Bukan bergantung pada model.
→ 422 injection_blocked
Input dibersihkan lalu diperlakukan sebagai data. Aturan tetap berlaku.
3
Scope Guard — batas domain
Klasifikasi niat: in_scope, off_topic, religious_ruling. Pertanyaan fatwa/hukum agama tidak pernah dijawab AI.
→ 422 out_of_scope
Off-topic ditolak. Fatwa dialihkan: "itu ranah ulama, saya carikan ustadznya."
4
Parse niat → parameter terstruktur
Mesin aturan lokal mengekstrak: bidang, kota, jenis acara, hari, jam, jumlah jemaah, preferensi gender. Tanpa panggilan jaringan.
5
Cari di basis data ustadz
Filter profil, bidang keahlian, kota, tarif, rating. Setiap hasil disitasi — agent hanya menyebut ustadz yang benar-benar ada di katalog.
6
Cultural Rules Check — aturan budaya Islam
Bentrok Salat Jumat (Jumat 11:30–13:00), tumpang tindih waktu salat, preferensi gender (ustadz/ustadzah), kewajaran durasi.
→ minta klarifikasi
Jadwal bertabrakan ditolak, bukan dipaksakan. Alternatif konkret ditawarkan.
7
Cukup informasi?
Jika parameter wajib belum lengkap, agent bertanya — tidak menebak lalu mengeksekusi.
→ pertanyaan balik
"Bidang kajian apa, dan di kota mana?"
8
Susun rencana (plan), belum eksekusi
Keluaran berupa kartu rencana: ustadz, acara, hari, waktu, lokasi. Tidak ada perubahan status apa pun di tahap ini.
9
⏸ Human-in-the-Loop — menunggu persetujuan eksplisit
Titik henti wajib. Agent berhenti dan menunggu kata persetujuan ("setuju", "ya", "lanjut"). Tidak ada jalur yang melewati langkah ini.
→ tetap berhenti
Tanpa persetujuan, tidak ada yang dicatat. Diam berarti belum setuju.
10
Eksekusi — catat booking
Hanya berjalan setelah langkah 9. Status berubah menjadi confirmed dan muncul di halaman Booking.
11
Audit Log — setiap langkah tercatat
Waktu, langkah, keputusan, alasan, dan hasil. Dapat dibuka pengguna kapan saja dari halaman /asisten.
Trust boundary 2 Hanya teks jawaban yang dikirim keluar. Kunci API tidak pernah menyentuh browser; keputusan menolak/mengizinkan dibuat sebelum panggilan jaringan.
Zona 3 — LLM eksternal (opsional, di luar kendali)
12
DeepSeek deepseek-flash → cadangan OpenRouter mistral-nemo
Dipakai hanya untuk memperhalus bahasa jawaban yang sudah diputuskan lokal. Penolakan, pemblokiran, dan rencana booking tidak memanggil LLM sama sekali. Keluaran model divalidasi ulang sebelum ditampilkan.
Langkah normal — berjalan otomatis di server
Guard — penolakan deterministik, tidak bisa dinegosiasi
Percabangan — agent berhenti untuk bertanya atau menolak
Persetujuan manusia — titik henti wajib sebelum eksekusi
Audit / eksternal — jejak dan pihak ketiga
